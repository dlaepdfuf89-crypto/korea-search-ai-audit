What a client audit bundle looks like

This public sample explains the workflow produced by RC13 without exposing the paid executable. It is based on the same automated sample-fixture workflow used for release QA.

1. Before audit

The toolkit detects a known OpenAI discovery-feed or Google-compatible feed profile, validates the catalog, and records findings rather than silently rewriting merchant facts.

2. Safe fix copy + change log

Safe Fix is deliberately conservative. It can normalize formatting such as surrounding whitespace and records each changed field with before/after evidence. It does not invent missing price, availability, brand, identifiers or other merchant facts.

3. Recheck

The fixed copy is audited again so the handoff can distinguish what changed from what still requires merchant input. Unknown OpenAI availability is not converted into a false Google stock state.

4. Client bundle

  • Before-audit result
  • Safe FIXED catalog copy
  • Per-change audit log
  • After-fix recheck
  • Source-aware evidence
  • Optional public-page audit evidence
  • Summary JSON
