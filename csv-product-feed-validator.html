CSV Product Feed Validator Workflow for Ecommerce Agencies

A product-feed validator is most useful when it does more than return a score. For repeat client work, the workflow should preserve the source catalog, identify actionable defects, make only deterministic fixes, record evidence and validate the result again.

Before validating a CSV or TSV

  • Keep the original client file unchanged.
  • Identify the intended target profile before interpreting fields.
  • Confirm the delimiter and headers instead of assuming every catalog uses the same layout.
  • Treat merchant facts such as price, stock, brand and identifiers as data that must not be invented.

What to validate

  • Required fields for the selected feed profile
  • Empty required values
  • Duplicate product IDs
  • Absolute product and image URLs
  • Price and currency representation
  • Accepted availability values
  • Conditional identifiers and brand requirements

Safe fixes versus merchant decisions

Trimming accidental surrounding whitespace is a deterministic normalization. Guessing a missing GTIN, changing unknown inventory to in-stock, or inventing a brand is not. A useful validator should keep those categories separate.

Why a changelog matters

For client work, record the item ID, field, before value, after value and reason for every automatic edit. That gives the merchant a reviewable trail and makes a second validation meaningful.

Validate again after the fix

The fixed copy should go through the target-profile validator again. The final handoff should clearly distinguish resolved formatting issues from facts that still require merchant input.
