How to Validate an OpenAI Product Feed Before Client Handoff

For the OpenAI Stable file-upload profile, validate the catalog as a data contract before trying to “improve” it. A preflight should identify structural defects without inventing merchant facts.

Reference checked 2026-09-29. OpenAI specifications can change. Confirm current official documentation before production use.

Current onboarding scope: OpenAI states that product-feed onboarding in ChatGPT is currently available to approved partners. A clean local preflight helps prepare a catalog, but it does not grant partner access or activate ingestion.

Required Stable discovery fields

The published Stable profile requires these nine basic fields for each purchasable item:

  • item_id
  • title
  • description
  • url
  • brand
  • seller_name
  • image_url
  • availability
  • price

Availability deserves a separate check

The Stable profile allows in_stock, out_of_stock, pre_order, backorder and unknown. If the same catalog will later be converted to another profile, do not silently translate unknown into a factual stock state.

Validate URLs and price representation

  • Product URLs and image URLs should be absolute rather than relative paths.
  • Price should follow the target format, including an ISO currency code.
  • Duplicate item IDs should be surfaced before handoff.
  • Do not fabricate missing brand, seller, inventory or price data just to obtain a passing result.

Keep evidence for automatic changes

Safe deterministic normalization, such as trimming surrounding whitespace, is different from supplying missing business data. Record every automatic change with field, before value, after value and reason, then validate the fixed copy again.

When a Google-compatible copy is also needed

Run a separate target-profile preflight after conversion. Seller identity and availability handling are not identical across the two workflows.
